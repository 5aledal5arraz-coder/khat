# ربط YouTube Analytics — خطوات جوجل كلاود

الهدف: يقدر الموقع يقرأ **أعمار الجمهور والدول** — أرقام القناة الخاصة اللي
`YOUTUBE_API_KEY` ما يرجعها ولا مرة.

## ليش المفتاح ما يكفي (الخلفية)

| | المفتاح الحالي `YOUTUBE_API_KEY` | هذا الربط |
|---|---|---|
| الواجهة | YouTube **Data** API | YouTube **Analytics** API |
| يرجع | المشاهدات، المشتركين، بيانات الفيديو | الأعمار، الدول، فترات الذروة |
| نوع البيانات | عامة، يشوفها أي أحد | خاصة بمالك القناة |
| التوثيق | مفتاح | **OAuth** — موافقة من حساب المالك |

ما في مفتاح — مهما كانت صلاحياته — يرجع الأعمار والدول. هذي قاعدة جوجل، مو قيد
في الكود.

---

## ما يسويه خالد في الكونسول (مرة وحدة)

### ١. فعّل الواجهة

[console.cloud.google.com](https://console.cloud.google.com) ← اختر نفس المشروع
اللي فيه `YOUTUBE_API_KEY` ← **APIs & Services ← Library** ← دوّر
**YouTube Analytics API** ← **Enable**.

> لازم تكون داخل بحساب جوجل **المالك لقناة خط**. الحساب الغلط ينجح في كل
> الخطوات وبعدين يرجّع أرقام قناة ثانية — والموقع يرفضه تلقائياً، بس أسهل لك
> تبدأ صح.

### ٢. شاشة الموافقة

**APIs & Services ← OAuth consent screen**:
- النوع: **External**، والحالة تبقى **Testing** (ما نحتاج مراجعة من جوجل).
- **Test users**: أضف بريد حسابك. بدونها جوجل ترفض الموافقة.
- الصلاحيات المطلوبة (كلها **قراءة فقط**، ولا وحدة منها تقدر تعدّل القناة):
  - `.../auth/yt-analytics.readonly` — الأرقام نفسها
  - `.../auth/youtube.readonly` — للتأكد إن القناة المربوطة هي قناة خط

### ٣. أنشئ العميل

**Credentials ← Create Credentials ← OAuth client ID**:
- Application type: **Web application**
- **Authorized redirect URIs** — أضف **الاثنين** بالضبط، بدون سلاش زايد:
  ```
  https://khatpodcast.com/api/admin/youtube/oauth/callback
  http://localhost:3000/api/admin/youtube/oauth/callback
  ```

جوجل تعطيك **Client ID** و**Client Secret**. أرسلهم لي أو حطهم بنفسك.

### ٤. المتغيرات

في `.env.local` محلياً، وفي نسخة السيرفر عند النشر:

```bash
GOOGLE_OAUTH_CLIENT_ID=...
GOOGLE_OAUTH_CLIENT_SECRET=...
YOUTUBE_OAUTH_ENC_KEY=<openssl rand -base64 32>
```

`YOUTUBE_OAUTH_ENC_KEY` يشفّر الـ refresh token في قاعدة البيانات. ولّده بـ:

```bash
openssl rand -base64 32
```

> **مفتاح مختلف لكل بيئة**، ولا ينكتب في git أبداً. لو ضاع المفتاح، الحل هو
> إعادة الربط من الشاشة — ما فيه خسارة بيانات.

### ٥. اربط

افتح `/admin/youtube-analytics` واضغط «اربط الحساب» ← وافق في شاشة جوجل ←
ترجع للشاشة نفسها. بعدها اختر الفترة واضغط قياس.

## القرار اللي ينتظرك

الأرقام تُخزَّن **ومعها فترتها**، والفترة تنطبع جنب الرقم في صفحة الشراكات.
«٤٠٪ من السعودية» في ٢٨ يوم غير «٤٠٪» في سنة، والشركة اللي تسأل «منين؟» لازم
تلقى جواب.

الشاشة تعطيك أربع فترات: ٢٨ يوم · ٩٠ يوم · سنة · ٣ سنوات. **ما في خيار «عمر
القناة كامل»** عن قصد — يحتاج تاريخ بداية نخمّنه، ورقم ما نقدر نسمّي فترته
رقم ما نقدر ندافع عنه.

## ملاحظات أمنية (المعمول به فعلاً)

- **الـ refresh token مشفّر في قاعدة البيانات** بـ AES-256-GCM، مو في
  `config/` — لأن `config/` متتبَّع في git، وأي سر ينحط فيه ينرفع مع الكود.
- **الربط والقياس وإلغاء الربط: للمالك (OWNER) فقط**، ويُتحقق منه داخل كل
  Server Action لحاله لا في الصفحة بس.
- **التحقق من القناة**: بعد الموافقة يقرأ الموقع أي قناة وافقت، وإذا مو قناة خط
  **يرفض ولا يخزّن شي** — لأن الحساب الغلط ينجح بصمت وينشر أرقام قناة غريبة في
  صفحة الرعاة.
- **حماية CSRF**: قيمة `state` عشوائية في الرابط وفي كوكي httpOnly، وتتقارن
  بـ `timingSafeEqual`. بدونها يقدر أحد يخلي المالك يربط قناة المهاجم.
- **الشاشة تقرأ آخر نتيجة، مو وجود الصف**: لو ألغيت الصلاحية من حسابك في جوجل،
  الصف يبقى ويفك تشفيره عادي — فالشاشة تعرض آخر خطأ بنفس وضوح حالة النجاح.
- **إلغاء الربط من الموقع لا يلغيه من جوجل.** للإلغاء الكامل: حسابك في جوجل ←
  الأمان ← تطبيقات لها وصول إلى حسابك.
